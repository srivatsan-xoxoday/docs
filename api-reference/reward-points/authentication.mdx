The Reward Points API uses OAuth 2.0 Bearer token authentication, consistent with all other Plum APIs. You generate a company-level access token using your Client ID and Secret, then use that company token to create user-scoped tokens for individual reward operations.

## Environment URLs

| Environment | OAuth Base URL |
|-------------|----------------|
| Production  | `https://accounts.xoxoday.com/chef` |
| Sandbox     | `https://canvas.xoxoday.com/chef` |

Use the sandbox environment during development. Your Client ID and Secret ID are different in each environment.

## Step 1: Generate your Client ID and Secret

<Steps>
  <Step title="Sign in to the Plum admin portal">
    Log in using Super Admin credentials. Only Super Admins can generate API credentials.
  </Step>
  <Step title="Navigate to API settings">
    Click **Settings** in the top navigation, select **API** from the left panel, and open the **Storefront Integration** tab.
  </Step>
  <Step title="Generate credentials">
    Click **Generate ID**, confirm the dialog, and copy your Client ID and Secret ID. Store them securely.
  </Step>
</Steps>

## Step 2: Obtain an access token

Use the OAuth 2.0 authorization code flow to obtain your company access token.

First, redirect to the authorization endpoint:

```bash
GET {OAUTH_BASE_URL}/v1/oauth/authorize
  ?client_id=YOUR_CLIENT_ID
  &response_type=code
  &redirect_uri=YOUR_REDIRECT_URI
  &scope=
  &state=YOUR_STATE_VALUE
```

After authorization, exchange the returned code for an access token:

<CodeGroup>
```bash curl
curl -X POST https://accounts.xoxoday.com/chef/v1/oauth/token/company \
  -H "Content-Type: application/json" \
  -d '{
    "grant_type": "authorization_code",
    "code": "YOUR_AUTHORIZATION_CODE",
    "redirect_uri": "YOUR_REDIRECT_URI",
    "client_id": "YOUR_CLIENT_ID",
    "client_secret": "YOUR_CLIENT_SECRET"
  }'
```

```javascript Node.js
const response = await fetch(
  'https://accounts.xoxoday.com/chef/v1/oauth/token/company',
  {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({
      grant_type: 'authorization_code',
      code: 'YOUR_AUTHORIZATION_CODE',
      redirect_uri: 'YOUR_REDIRECT_URI',
      client_id: 'YOUR_CLIENT_ID',
      client_secret: 'YOUR_CLIENT_SECRET',
    }),
  }
);
const { access_token, refresh_token } = await response.json();
```
</CodeGroup>

A successful response:

```json
{
  "access_token": "eyJ0eXAiOiJKV1QiLCJhbGci...",
  "token_type": "bearer",
  "expires_in": 2592000,
  "refresh_token": "3ecc3cfc35c624978b87dd6735bd1dab...",
  "access_token_expiry": 1692265307092,
  "refresh_token_expiry": 1694857307092
}
```

<Warning>
  The authorization code expires in **5 minutes**. Exchange it for tokens immediately.
</Warning>

## Step 3: Create a user token

With your company access token, you can create a user-scoped token by calling `POST /create-user-token`. See the [Endpoints reference](/api-reference/reward-points/endpoints) for the full request schema.

## Token lifecycle

| Token | Validity |
|-------|----------|
| Access token | 15 days |
| Refresh token | 30 days |

Refresh your access token before it expires:

```bash
curl -X POST https://accounts.xoxoday.com/chef/v1/oauth/token/refresh \
  -H "Content-Type: application/json" \
  -d '{
    "grant_type": "refresh_token",
    "refresh_token": "YOUR_REFRESH_TOKEN",
    "client_id": "YOUR_CLIENT_ID",
    "client_secret": "YOUR_CLIENT_SECRET"
  }'
```

## Include the token in requests

Add the access token to every API request as a Bearer token:

```bash
curl -X GET https://accounts.xoxoday.com/chef/v1/oauth/api/fetch-points \
  -H "Authorization: Bearer YOUR_ACCESS_TOKEN" \
  -H "X-Api-Key: YOUR_CLIENT_ID" \
  -H "X-Secret-Key: YOUR_CLIENT_SECRET"
```
