Plum by Xoxoday provides a suite of REST APIs that let you programmatically send rewards, manage points balances, distribute reward links, surface employee perks, and integrate the full reward catalog into your own application. Every API uses OAuth 2.0 for authentication and communicates exclusively over HTTPS using JSON-encoded request and response bodies.

## Base URLs

All Plum APIs share the same base URL pattern. Use the sandbox environment while you build and test your integration, then switch to the production URL when you go live.

| Environment | Base URL |
|-------------|----------|
| Production  | `https://accounts.xoxoday.com/chef` |
| Sandbox     | `https://canvas.xoxoday.com/chef` |

<Note>
  Your Client ID and Secret ID differ between sandbox and production environments. Make sure you use the correct credentials for each environment.
</Note>

## Authentication summary

Every request to a Plum API must include three HTTP headers: your Client ID, your Secret ID, and a Bearer access token. You generate the access token once via the OAuth 2.0 authorization flow and refresh it before it expires. See the [Authentication guide](/api-reference/authentication) for step-by-step instructions.

## Request format

All request bodies must be valid JSON encoded in UTF-8. Set the `Content-Type` header to `application/json` on every POST request. Responses are also returned as JSON.
