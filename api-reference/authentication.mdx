---
title: "Authenticate with the Plum Rewards API"
description: "Learn how to get your Client ID and Secret from the Plum admin portal, generate an OAuth 2.0 access token, and authenticate every API request."
---

All requests to any Plum API must be authenticated. Plum uses the OAuth 2.0 protocol with Bearer token authentication. Every HTTP request must include your Client ID, Secret ID, and a valid access token in the request headers. This guide walks you through generating your credentials and obtaining your first access token.

## Environment URLs

Choose the correct OAuth base URL for your target environment.

| Environment | OAuth Base URL |
|-------------|----------------|
| Production  | `https://accounts.xoxoday.com/chef` |
| Sandbox     | `https://canvas.xoxoday.com/chef` |

Start with the sandbox environment while you develop and test. When you are ready to go live, replace the sandbox URL and credentials with your production values.

## Step 1: Get your Client ID and Secret

<Steps>
  <Step title="Log in to the Plum admin portal">
    Sign in to your Xoxoday account at the admin portal using your Super Admin credentials. Only Super Admins can generate API credentials.
  </Step>
  <Step title="Navigate to API settings">
    Click the **Settings** tab in the top navigation bar, then select **API** from the left panel. Open the **Storefront Integration** tab.
  </Step>
  <Step title="Generate your Client ID">
    Click the **Generate ID** button. A confirmation dialog will appear. Confirm to generate your Client ID and Secret ID. Both values will be displayed on the dashboard—copy them to a secure location.
  </Step>
</Steps>

<Warning>
  Store your Client ID and Secret ID securely. Never expose them in client-side code, public repositories, or logs.
</Warning>

## Step 2: Request an authorization code

Redirect the user (or your server process) to the authorization endpoint with your Client ID and redirect URI:

```bash
GET {OAUTH_BASE_URL}/v1/oauth/authorize
  ?client_id=YOUR_CLIENT_ID
  &response_type=code
  &redirect_uri=YOUR_REDIRECT_URI
  &scope=
  &state=YOUR_STATE_VALUE
```

After the user authenticates and grants access, Plum redirects to your `redirect_uri` with a short-lived authorization code in the query string.

<Warning>
  The authorization code is valid for only **5 minutes**. Exchange it for an access token immediately.
</Warning>

## Step 3: Exchange the code for an access token

Use the authorization code to request an access token and a refresh token.

<CodeGroup>
```bash curl
curl -X POST https://accounts.xoxoday.com/chef/v1/oauth/token/company \
  -H "Content-Type: application/json" \
  -d '{
    "grant_type": "authorization_code",
    "code": "YOUR_AUTHORIZATION_CODE",
    "redirect_uri": "YOUR_REDIRECT_URI",
    "client_id": "YOUR_CLIENT_ID",
    "client_secret": "YOUR_CLIENT_SECRET"
  }'
```

```javascript Node.js
const response = await fetch(
  'https://accounts.xoxoday.com/chef/v1/oauth/token/company',
  {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({
      grant_type: 'authorization_code',
      code: 'YOUR_AUTHORIZATION_CODE',
      redirect_uri: 'YOUR_REDIRECT_URI',
      client_id: 'YOUR_CLIENT_ID',
      client_secret: 'YOUR_CLIENT_SECRET',
    }),
  }
);
const data = await response.json();
console.log(data.access_token);
```
</CodeGroup>

A successful response looks like this:

```json
{
  "access_token": "eyJ0eXAiOiJKV1QiLCJhbGci...",
  "token_type": "bearer",
  "expires_in": 2592000,
  "refresh_token": "3ecc3cfc35c624978b87dd6735bd1dab...",
  "access_token_expiry": 1692265307092,
  "refresh_token_expiry": 1694857307092,
  "email": "you@yourcompany.com"
}
```

Store both the `access_token` and `refresh_token` securely—you will need the refresh token to extend your session without re-authorizing.

## Step 4: Include the token in API requests

Pass the access token as a Bearer token in the `Authorization` header of every API request, alongside your Client ID and Secret ID.

```bash
curl -X GET https://accounts.xoxoday.com/chef/v1/oauth/api/get-filters \
  -H "Authorization: Bearer YOUR_ACCESS_TOKEN" \
  -H "X-Api-Key: YOUR_CLIENT_ID" \
  -H "X-Secret-Key: YOUR_CLIENT_SECRET"
```

## Token lifecycle and refresh

| Token | Validity |
|-------|----------|
| Access token | 15 days |
| Refresh token | 30 days |

Use the refresh token to generate a new access token before the current one expires. You can refresh within the 15-day access token window, and you also have an additional 15-day grace period after the access token expires (as long as the refresh token itself has not expired).

```bash
curl -X POST https://accounts.xoxoday.com/chef/v1/oauth/token/refresh \
  -H "Content-Type: application/json" \
  -d '{
    "grant_type": "refresh_token",
    "refresh_token": "YOUR_REFRESH_TOKEN",
    "client_id": "YOUR_CLIENT_ID",
    "client_secret": "YOUR_CLIENT_SECRET"
  }'
```

<Tip>
  Automate token refresh in your application so your integration never goes offline due to an expired token. Store the token and its expiry timestamp, and proactively refresh a few hours before expiry.
</Tip>

If you lose both your access token and refresh token, you must restart the full OAuth flow from Step 2.
